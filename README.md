# 北京休闲娱乐场所批量采集工具（高德地图 + 大众点评核验）

从**高德地图**按分类关键词批量采集北京“休闲娱乐”场所，按业务规则过滤后，再到**大众点评**核验同店存在，
最后清洗去重并导出 21 列的 xlsx 表格。提供**命令行工具**与**网页控制台**两种用法。

---

## 零、准备数据文件（首次使用必读）

本仓库**不包含业务数据**，运行前需要自行准备两个只读输入文件（放在项目根目录）：

| 文件 | 内容 | 示例 |
| --- | --- | --- |
| `fl.txt` | 分类字典：12 个分类的 `code` / 中文名 | `fl.example.txt` |
| `cs.txt` | 已有场所清单：用于采集去重，其 `type_code` 同时是分类判定的回归样本 | `cs.example.txt` |

```bash
# Windows
copy fl.example.txt fl.txt
copy cs.example.txt cs.txt

# Linux / macOS
cp fl.example.txt fl.txt && cp cs.example.txt cs.txt
```

说明：真实 `cs.txt` 可能由多个分页 JSON 文档首尾拼接而成（非法 JSON），
[src/data/reference.js](src/data/reference.js) 已用「字符串感知的括号配平」兼容解析，多段与单段均可。

## 一、快速开始

```bash
cd D:\爬虫脚本\csjb
npm install                 # 只装 3 个依赖（playwright / express / exceljs），不需要下载浏览器

npm run collect -- --limit 5              # ① 直接采集：脚本会自动新开一个“普通模式”浏览器窗口
#    → 首次运行请在窗口里登录【高德地图】与【大众点评】，登录一次即可长期保留

npm run web                               # ② 或启动网页控制台 http://127.0.0.1:5178
```

> **浏览器说明（本机为 Microsoft Edge）**
> 本机没有安装 Google Chrome，程序会自动探测并使用 **Microsoft Edge**（同为 Chromium 内核），
> 探测顺序为 Edge → Chrome，配置项在 `config/rules.json` 的 `amap.browserChannel`（`auto` 即自动）。
>
> **为什么每次都用“普通模式”新开一个窗口？**
> 高德使用阿里 baxia 风控，会识别 Playwright 直接启动的浏览器（带 `--no-sandbox` / `--enable-automation`
> 等自动化标记），导致滑块验证码**无法通过**、详情页数据被拦截。
> 因此每次运行采集或网页控制台时，程序都会：
> ① 先关闭正在占用 profile 的旧窗口（登录态保留在 profile 中，不会丢失）；
> ② 以普通方式（不带任何自动化标记）**新建一个浏览器窗口**，并开放调试端口；
> ③ 通过 CDP 只“接管”这个窗口 —— 浏览器本身没有任何自动化痕迹，滑块可以正常通过。
>
> 想提前手动登录时，也可以单独执行 `npm run browser`，它同样以普通模式新建窗口并停在登录页。
>
> 相关开关在 `config/rules.json` 的 `amap` 段：
> `launchMode`（`cdp`=普通模式新建并接管，默认；`persistent`=Playwright 直接启动）、
> `reuseExistingBrowser`（是否复用已开的调试端口窗口，默认 `false`）、
> `closeProfileBeforeLaunch`（启动前是否释放 profile，默认 `true`）。

## 二、命令行参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--limit N` | 采集数量上限（通过**全部**规则的场所数量） | 不限制 |
| `--categories KTV,TQG` | 只采集指定分类（code 或中文名，逗号分隔） | 全部 12 个分类 |
| `--delay 2000` | 每个浏览器操作的间隔（毫秒） | 2000 |
| `--min-photos 5` | 高德封面照片数下限（需**大于**该值） | 5 |
| `--closing-after 23:00` | 结束营业时间必须晚于该时间 | 23:00 |
| `--max-pages 10` | 每个关键词最多翻页数 | 10 |
| `--out DIR` | 结果目录 | `D:/Code/csjb` |
| `--skip-verify` | 跳过大众点评核验（提速） | 关闭 |
| `--resume` | 复用本地缓存（断点续采） | 关闭 |
| `--json` | 以 JSON 输出结果摘要（供脚本调用） | 关闭 |

示例：

```bash
npm run collect -- --limit 10 --categories KTV,TQG,JBS     # 只采 KTV / 台球馆 / 剧本杀
npm run collect -- --limit 3 --skip-verify                 # 不核验点评，快速试跑
npm run collect -- --limit 20 --resume                     # 续采（复用已抓取的详情与核验结果）
```

## 三、网页控制台

```bash
npm run web      # 然后浏览器打开 http://127.0.0.1:5178
```

页面包含**一个数字输入框**和**一个“开始采集”按钮**：输入的数字即本次采集数量上限，点击后：
1. 自动打开/接管浏览器窗口，等待你登录高德与大众点评；
2. 实时显示进度（已扫描 / 已通过 / 已过滤 / 已核验）与彩色日志；
3. 结束后显示生成的 xlsx 路径，可一键打开结果目录。

## 四、过滤规则（全部满足才会写入表格）

1. **不与已有场所重名**：与 `cs.txt` 中 662 条已有场所做归一化比对（去分店后缀、全半角、标点），并做本次采集内部去重；
2. **分类必须属于 `fl.txt`**：12 个分类（KTV / 台球馆 / 棋牌 / 麻将馆 / 休闲按摩足浴 / 主机游戏 / 私人影院 / 剧本杀 / Live House / 精酿酒吧 / 特调酒吧 / 夜店），
   判定规则由 `cs.txt` 的 662 条已标注样本学习而来（`config/categories.json`），名称判不出时用高德分类文本兜底，仍判不出则丢弃；
3. **照片数 > 5**：取高德详情页**封面右下角「照片N」**的数字。
   （⚠️ 不要用相册区「共 N 张」——未登录时只显示 3 张，不可信）；
4. **正常营业且结束营业时间 > 23:00**：兼容 `11:00-24:00`、`12:00-次日05:00`、`24小时营业` 等写法；
5. **大众点评有同店**：按店名搜索，三档判定
   ① 店名归一化比对（并要求**分店信息兼容**，避免连锁不同分店误判）
   ② 地址相似度（门牌号 + 道路名 + 二元组，默认阈值 0.45）
   ③ 地标反查（如点评“红莲南路**中国文化大厦**B1层” ↔ 高德“红莲南路**57号**”）
   营业状态显示「**休息中**」也算正常营业；只有歇业 / 关闭 / 暂停营业 / 查不到才算不通过。

## 五、输出文件

| 文件 | 说明 |
| --- | --- |
| `D:\Code\csjb\场所采集_时间戳.xlsx` | 结果表：**21 列**，一行一个场所，最后一列为「照片数量」 |
| └ 工作表 `场所列表` | 城市 / 区县 / 场所名称 / 详细地址 / 场所类型（中文名）/ 纬度 / 经度 / 联系电话 / 微信号 / 营业时间 / 封面图 / 人均消费 / 评分 / 描述 / 设施标签 / 特色标签 / 来源 / 来源 ID / 是否推荐 / 排序权重 / **照片数量** |
| └ 工作表 `采集明细` | 追溯信息：高德 POI ID、高德分类文本、归类结果、营业状态、大众点评店名/地址/链接、同店判定方式、核验说明、告警 |
| `data\reports\rejected_时间戳.csv` | 被过滤条目明细（含过滤原因），便于复核规则是否过严/过松 |
| `data\cache\` | 断点续采缓存（搜索结果 / 详情 / 核验结果），配合 `--resume` 使用 |
| `data\logs\` | 运行日志 |

说明：`封面图`列留空（按需求后续人工上传）；`微信号`高德无数据源，留空；`描述`留空；`来源`为 `amap`；`来源 ID`为高德 POI ID。
`是否推荐` 由评分自动判定：**评分严格高于 4.1 记为「推荐」，否则「不推荐」**。
高德未提供评分时，评分列按兜底值 **4.0** 记（`config/rules.json` 的 `defaults.rating`），4.0 不高于阈值故判为「不推荐」；
阈值见 `recommendRatingAbove`。评分列与是否推荐列共用同一个值，二者始终自洽。

## 七、常见问题

**Q：提示「浏览器 profile 正被占用」？**
采集启动时会自动关闭占用该 profile 的旧窗口，通常不会遇到。若仍出现，执行 `npm run close-browser`
（或手动关闭该窗口）后重试；登录态保存在 `.browser-profile` 里，不会丢失。

**Q：滑块验证码一直提示「验证失败」？**
说明当前窗口被识别为自动化环境（例如用 `launchMode: "persistent"` 由 Playwright 直接启动）。
执行 `npm run close-browser` 关掉它，再运行采集（程序会以普通模式新建窗口）；
也可先执行 `npm run browser` 手动新建普通窗口再重试。

**Q：手机号/电话抓成了备案号？**
已按 `0xxx-xxxxxxx` / `400xxxxxxx` / `1[3-9]xxxxxxxxx` 严格匹配，不会把页面底部的备案号（如 `11010502056787`）当成电话。

**Q：采集很慢？**
需求要求“每个浏览器操作间隔 2 秒”（`--delay` 可调）。单条场所大约需要 20~30 秒（详情页 + 点评搜索 + 店铺页核验），
所以 `--limit 20` 大约需要 8~12 分钟。`--skip-verify` 可明显提速。

**Q：想扩大采集范围？**
调大 `--max-pages`（每个关键词翻页数）；分类关键词在 `config/categories.json` 的 `amapQuery` 中配置。
